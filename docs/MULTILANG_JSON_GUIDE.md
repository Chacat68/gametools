# GameTools v1.39.5 功能说明文档

> **历史文档**：记录 v1.39.5 批量改表多语言 JSON 能力。当前支持语言以 `core/constants.py` 的 `SUPPORTED_LANGUAGES`（zh / vn / th / en）及 [BATCH_MODIFIER_GUIDE.md](BATCH_MODIFIER_GUIDE.md) 为准；GUI 路径请在 **工作台** 选择。

**版本号**: 1.39.5  
**发布日期**: 2025-12-16  
**主要功能**: 批量改表支持根据用户选择的语言加载JSON配置

---

## 🎯 新增功能概述

v1.39.5 版本增强了批量改表功能，支持从包含多种语言配置的JSON文件中，根据用户在GUI中选择的目标语言动态加载对应的配置内容。

### 关键特性

1. **多语言JSON支持**
   - 一个JSON文件可以包含多种语言的配置
   - 系统根据用户选择自动加载对应语言的内容
   - 语言代码不匹配时自动使用第一个可用语言

2. **智能语言识别**
   - 自动检测JSON中所有可用的语言
   - 支持常见语言代码映射（中文、越南语、泰语等）
   - 提供语言列表查询API

3. **向后兼容**
   - 完全兼容v1.39.0-v1.39.4的JSON格式
   - 不影响自动匹配模式的使用
   - 传统单语言JSON继续正常工作

## 📝 使用方法

### 场景1: 多语言JSON配置

**JSON文件示例**:
```json
{
    "ZH": {
        "text_tables": [
            {
                "table_name": "armor.xlsx",
                "fields": ["des_zh", "name_zh", "title_zh"]
            }
        ]
    },
    "VN": {
        "text_tables": [
            {
                "table_name": "armor.xlsx",
                "fields": ["des_vn", "name_vn", "title_vn"]
            }
        ]
    },
    "TH": {
        "text_tables": [
            {
                "table_name": "armor.xlsx",
                "fields": ["des_th", "name_th", "title_th"]
            }
        ]
    },
    "EN": {
        "text_tables": [
            {
                "table_name": "armor.xlsx",
                "fields": ["des_en", "name_en", "title_en"]
            }
        ]
    }
}
```

**GUI操作步骤**:

1. **自动匹配模式**（推荐）
   - 选择JSON配置文件
   - 勾选"自动匹配语言"
   - 系统自动使用第一个语言（ZH）

2. **手动模式**
   - 选择JSON配置文件
   - 取消勾选"自动匹配语言"
   - 在"目标语言列"中输入: `越南语` 或 `VN` 或 `vn`
   - 系统将加载VN配置的内容

### 场景2: 单语言JSON配置（向后兼容）

**JSON文件示例**:
```json
{
    "language": {"code": "vn", "name": "越南语"},
    "text_tables": [
        {
            "table_name": "armor.xlsx",
            "fields": ["des_vn", "name_vn"]
        }
    ]
}
```

**行为**: 
- 无论选择什么目标语言，都使用JSON中的配置
- 与v1.39.4完全相同

## 🔧 技术细节

### 支持的语言代码

| 语言 | 代码选项 | 示例 | 备注 |
|------|---------|------|------|
| 中文 | zh, cn, ZH, CN | `"ZH": {...}` | 当前产品主流程 |
| 越南语 | vn, VN | `"VN": {...}` | 当前产品主流程 |
| 泰语 | th, TH | `"TH": {...}` | 当前产品主流程 |
| 英语 | en, EN | `"EN": {...}` | 当前产品主流程 |
| 日语 | jp, JP | `"JP": {...}` | 历史 JSON 可能出现；非 `SUPPORTED_LANGUAGES` 默认识别 |
| 韩语 | kr, KR | `"KR": {...}` | 历史 JSON 可能出现 |
| 繁体 | tw, TW | `"TW": {...}` | 历史 JSON 可能出现 |

### GUI中的语言输入

在"目标语言列"中可以输入：

- **语言名称**: 中文、越南语、泰语、英语、繁体
- **语言代码**: zh, vn, th, en, tw
- **大写代码**: ZH, VN, TH, EN, TW

系统会自动转换为标准的小写语言代码。

## 📊 实际应用示例

### 示例1: 同时维护三个语言版本

**项目结构**:
```
project/
├── config/
│   └── fields_multilang.json  (包含ZH、VN、TH配置)
├── mapping.xlsx               (映射表)
└── excel_files/               (待修改的Excel文件)
```

**操作流程**:

1. **修改中文版本**
   - 自动模式：直接执行（使用第一个语言ZH）
   - 手动模式：目标语言列输入"中文"

2. **修改越南语版本**
   - 手动模式：目标语言列输入"越南语"
   - 系统加载VN配置并匹配对应字段

3. **修改泰语版本**
   - 手动模式：目标语言列输入"泰语"
   - 系统加载TH配置并匹配对应字段

**优势**:
- 只需维护一个JSON配置文件
- 各语言版本的字段配置集中管理
- 切换语言时无需更换JSON文件

### 示例2: 多项目共享配置

**场景**: A项目和B项目使用相同的表结构，但有不同的语言需求

**配置文件**: `shared_config.json`
```json
{
    "ZH": {"text_tables": [...]},
    "VN": {"text_tables": [...]},
    "TH": {"text_tables": [...]}
}
```

**A项目**: 只需要中文和越南语
- 使用相同的JSON文件
- 分别选择"中文"和"越南语"执行

**B项目**: 只需要泰语
- 使用相同的JSON文件
- 选择"泰语"执行

## ⚠️ 注意事项

### 1. 语言代码匹配

- JSON中的语言key必须是支持的语言代码（如ZH、VN、TH）
- GUI输入的语言会自动映射到对应代码
- 不区分大小写（VN和vn都可以）

### 2. 语言不匹配时的行为

**情况**: JSON有{ZH, VN}，用户选择"泰语"

**系统行为**:
```
⚠️ 未找到语言 'th'，使用 'ZH'
```
- 输出警告信息
- 自动使用第一个可用语言
- 继续执行（不会中断）

### 3. 自动模式 vs 手动模式

| 模式 | 语言选择 | 适用场景 |
|------|---------|----------|
| 自动模式 | 使用第一个语言 | JSON只有一个语言，或主要使用第一个语言 |
| 手动模式 | 用户指定语言 | JSON有多个语言，需要切换不同语言 |

### 4. JSON格式要求

- **格式3（推荐）**: 语言代码作为顶层key
  ```json
  {"ZH": {...}, "VN": {...}}
  ```

- **格式1/2（兼容）**: 使用language字段
  ```json
  {"language": {"code": "vn"}, "text_tables": [...]}
  ```

格式3支持多语言配置，格式1/2只能单语言。

**兼容性**: 完全兼容，无需修改现有JSON配置

**建议操作**:
1. 备份现有JSON文件
2. （可选）合并多个单语言JSON为一个多语言JSON

**示例 - 合并JSON**:

**原有文件**:
- `config_zh.json`: 中文配置

**合并后**:
`config_all.json`:
```json

}
```

**优势**: 统一管理，无需切换文件
